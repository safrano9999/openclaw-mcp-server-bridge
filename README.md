# OpenClaw MCP Server Bridge

A private, in-process MCP endpoint for controlling selected OpenClaw agents through their existing messaging channels. Telegram keeps OpenClaw’s bot accounts, admission rules, pairing and bindings. The bridge adds no bot poller, container or listening port.

## Configure selected agents

The extension’s `env.example` defines repeatable agent/bearer pairs. The standard `config.sh` new/skip flow lets you add each pair and enter a bearer or generate one with `openssl rand -hex 32`. The resulting values live in your host `.env`:

```dotenv
OPENCLAW_MCP_BRIDGE_AGENT=carassistant
OPENCLAW_MCP_BRIDGE_BEARER=<your-generated-bearer>

OPENCLAW_MCP_BRIDGE_AGENT_02=another-agent
OPENCLAW_MCP_BRIDGE_BEARER_02=<another-generated-bearer>
```

Only complete pairs for existing OpenClaw agents are enabled. Unknown agents and incomplete pairs are skipped. Empty pairs clear the selection and old credentials; absent pair variables leave independently managed configuration intact. Each agent and each bearer must be unique. Bearers accept 43–128 URL-safe characters, including the 64-character hexadecimal value generated by the example.

Run the extension-owned init after `openclaw-ephemeral configure` has generated `openclaw.json` and before starting the gateway:

```sh
python3 image/init/20-openclaw-mcp-bridge.py
```

The init uses the native `openclaw config set --batch-file` writer to replace `agentIds` and `credentials` together, preserving other plugin settings and channel configuration. The temporary batch file is private and removed after the write; bearers do not appear in command-line arguments. Repeated initialization with the same pairs does nothing. Removing a pair revokes that bearer.

For Fedora’s existing init-hook runner, install the script under `/usr/local/share/fedora45-ai/init.d/OPENLAW/20-openclaw-mcp-bridge.py`. The same script works on bare metal with Python 3 and OpenClaw on `PATH`. Use the existing `OPENCLAW_CONFIG` or `OPENCLAW_CONFIG_PATH` to select the configuration file. Inject the environment file into the init process; the script does not source arbitrary shell files.

The extension uses the supplied bearers and never generates replacements. Keep your host `.env` persistent and private so each client can reuse its bearer after container recreation. Credentials must never be included in an image or Git. You can also configure `agentIds` and `credentials` directly through OpenClaw for a bare-metal installation.

```sh
openclaw mcp-bridge status
openclaw mcp-bridge client-config carassistant --url https://your-gateway.example
```

`client-config` deliberately outputs that agent’s bearer. Keep it private. The MCP endpoint is `/mcp` on the existing gateway; remote access uses its existing HTTPS proxy. Opening `/mcp` in a browser shows a small connection page with its own favicon. The page and `/mcp/favicon.jpeg` are public static content; MCP calls require the assigned Bearer token.

## FIFO and current destination

Each agent has its own FIFO and exactly one current return route, `actual_channel`. Every accepted incoming message creates one FIFO entry and replaces that agent’s current route with its complete source: channel, account, destination, thread and session.

Incoming messages are admitted using the channel's sender authorization. Disabling automatic replies or denying outbound delivery does not discard an authorized incoming message. `send_message` separately checks the current outbound policy before sending.

For example, messages arriving through Telegram, then Discord, leave Discord as the current outgoing destination. Reading or draining older FIFO entries never changes the current route. Different agents keep independent queues and destinations.

There is no historical route selector. `send_message` accepts only text and always uses the most recently accepted source. The client cannot supply a chat ID or choose an older message’s destination. The latest return route for each agent is saved atomically in `<OpenClaw state directory>/openclaw-mcp-server-bridge/routes.json` and survives gateway restarts. Every newly accepted incoming message replaces that agent's saved destination, including its sender, channel, account and thread. FIFO consumption and message expiry never change it. The file contains no message bodies or bearer tokens and belongs on the existing persistent OpenClaw volume.

A first admitted incoming message is still required to establish a destination. Routing configuration changes or a session reset require a fresh admitted incoming message. A send whose destination changes before platform handoff is rejected rather than delivered to an outdated target.

| Tool | Input | Behavior |
| --- | --- | --- |
| `new_message` | Optional `count`, 1–100; default 1 | Atomically consume the oldest entries from this agent’s FIFO. |
| `pending_count` | None | Read pending, overflow, expiry and duplicate counters. |
| `send_message` | `text` | Send text to this agent’s current return route. |

An entry contains its ID, sequence, receipt time, text, truncation flag and original source metadata. Source metadata describes the incoming message; it does not select the outgoing destination. Message text is untrusted user content. Local paths, signed download URLs, tokens and internal history/prompt envelopes are excluded. Media binaries and outgoing attachments are outside this release.

## Delivery and lifetime

Each agent retains at most 1,000 messages / 8 MiB, with 32,768 characters per text and at most 8,192 deduplication identities. At most 64 agents are selected. Overflow drops the oldest entries and increments a counter. Messages expire after 24 hours; the current return route has no time-based expiry. Disconnecting an MCP client keeps the queue; restarting the gateway or bridge clears the queue and restores the saved return route.

Consumption is **at most once**: entries removed by `new_message` are not replayed after a lost HTTP response. Concurrent clients of the same agent share the queue and receive disjoint entries. There is no persistent inbox or acknowledgement protocol.

Outgoing text uses OpenClaw’s public durable delivery API. `sent` means the host confirmed delivery. `suppressed`, `partial_failed` and `delivery_unknown` do not mean complete success. The bridge never blindly retries uncertain delivery.

## Boundaries

The bearer identifies one agent. Every request and platform handoff checks that principal again. Host admission, Telegram pairing/allowlists, bindings, native commands, session generation and send policy remain authoritative. Selected ordinary agent dispatches are taken over before an LLM reply; unrelated agents retain normal behavior.

The HTTP endpoint requires a bearer, accepts JSON POST requests and rejects JSON-RPC batches. GET/DELETE return 405 after authentication. Browser origins are denied unless explicitly configured. Limits are 128 KiB per request, 64 simultaneous requests, eight sends per agent and a 60-second request timeout. TLS and public rate limiting belong to the existing gateway infrastructure.

Current takeover support targets admitted channel dispatches, primarily Telegram. Webchat/WebUI, ACP, cron/heartbeat and host-excluded runtimes are outside the supported takeover path. No model call is needed to queue a captured message or send MCP text.

## Install and release

```sh
sha256sum -c openclaw-mcp-server-bridge-latest.zip.sha256
openclaw plugins install --force --accept-capabilities ./openclaw-mcp-server-bridge-latest.zip
```

The ZIP includes the compiled extension, dependency license notices, `env.example` and the init script. MCP SDK 1.30.0 and Zod are bundled; public `openclaw/plugin-sdk/*` imports come from the host. No plugin-local dependency install is needed.

GitHub Actions verifies OpenClaw **2026.9.4** and **2026.10.6**, including public SDK imports, ZIP installation and isolated gateway startup. Unit tests cover FIFO order, the latest-source destination, agent isolation, admission, delivery policy and injected initialization. Production Telegram acceptance remains a separate live test.

Workflow source of truth: `SCRIPTS/githubactions/openclaw-mcp-server-bridge`; shared packaging: `SCRIPTS/githubactions/_shared/scripts/openclaw_plugin_zip.sh`. Container images are built only by the existing Fedora GitHub Actions, published to GHCR and pulled only through Smart1.

## Direct webhooks

Enable `OPENCLAW_MCP_BRIDGE_DIRECT=true` to accept JSON at `/mcp/direct` on the same gateway. It defaults to `false`. Authenticate with the existing bearer for the target agent; no separate webhook key or listening port is needed.

```http
POST /mcp/direct
Authorization: Bearer <agent-bearer>
Content-Type: application/json

{"text":"Location: 52.52, 13.405 (measured 2026-10-25T12:00:00Z)","event_id":"phone:1792929600","payload":{"latitude":52.52,"longitude":13.405}}
```

`text` is required. `event_id` and a structured `payload` object are optional. Other top-level fields are rejected. The bearer selects the agent; the request cannot choose a channel, recipient or session. Text is sent through the gateway to the saved latest channel destination using the same delivery policy as `send_message`. No LLM call is involved.

To make incoming webhook data readable by MCP clients as well, set `OPENCLAW_MCP_BRIDGE_DIRECT_FIFO=true` (default `false`). Each accepted webhook adds one `webhook` entry containing text and payload to that agent's existing FIFO. It **never changes the saved return route**, even if no route exists yet. Ordinary admitted channel messages still update the route as before. With FIFO enabled, duplicate `event_id` values are suppressed within the queue's existing deduplication window. Treat webhook payloads as untrusted input.

The response separates `fifo_enqueued` from outbound delivery. HTTP 200 with `status: sent` confirms channel delivery; HTTP 202 with `fifo_enqueued: true` confirms only FIFO acceptance when delivery failed or no channel route is available. Without FIFO, a missing route returns 409 and a denied send policy returns 403. Unknown delivery is never retried automatically. Queue limits, expiry and restart behavior remain the same as for channel inputs.
